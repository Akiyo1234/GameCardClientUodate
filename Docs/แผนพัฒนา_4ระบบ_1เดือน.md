## ข้อ 3 — เก็บ Log การเล่นลง DB  🟡 (~2-3 วัน)

### มีอยู่แล้ว
- `GameLog.Log` (Assets/Scripts/GameLog.cs) — log ทั่วไป ถูก strip ตอน release build (ยังใช้ต่อสำหรับ debug ใน editor)
- Pattern เขียน Supabase ชัดเจน: `PlayerDataService.CallAuthedFnAsync` (Edge Function) + REST insert

### งานที่ต้องทำ
- [ ] **SQL**: ตาราง `game_logs`
  ```sql
  create table public.game_logs (
    id          bigserial primary key,
    user_id     uuid references auth.users(id),
    room_code   text,
    match_id    text,                       -- session name + timestamp ของแมตช์
    event_type  text not null,              -- 'match_start','turn_taken',...
    payload     jsonb default '{}'::jsonb,  -- ข้อมูลเสริมต่อ event
    client_ts   timestamptz,                -- เวลาฝั่งเครื่อง (กันเวลาเครื่องเพี้ยน)
    created_at  timestamptz not null default timezone('utc', now())
  );
  alter table public.game_logs enable row level security;
  -- insert เฉพาะ row ของตัวเอง
  create policy "insert own logs" on public.game_logs
    for insert to authenticated with check (user_id = auth.uid());
  -- (option) ให้เจ้าของอ่าน log ตัวเอง; admin อ่านทั้งหมดผ่าน service_role
  create index idx_game_logs_match on public.game_logs(match_id);
  create index idx_game_logs_event on public.game_logs(event_type);
  ```
- [ ] **Client**: `GameLogger` (static service)
  - `GameLogger.LogEvent(string type, object payload = null)` → enqueue ลง list ในหน่วยความจำ
  - flush แบบ **batch** ทุก ~5 วิ หรือตอนจบรอบ/ปิดเกม → POST ไป `/rest/v1/game_logs` ทีละหลาย row (ลดจำนวน request)
  - แนบ `user_id` (จาก `SupabaseManager.Instance.Client.Auth.CurrentUser.Id`), `room_code`, `match_id` อัตโนมัติ
  - กัน fail เงียบ: ถ้าออฟไลน์/ไม่มี session → เก็บค้างไว้ flush รอบหน้า (อย่าให้ค้างเกมเด็ดขาด)
- [ ] **วาง log point** (ใช้ event ที่เกมยิงอยู่แล้ว):
  - `match_start` (จำนวนผู้เล่น, โหมด online/bot)
  - `turn_taken` (seat, action: pick_coins/buy_card/reserve_card)
  - `card_bought` / `card_reserved` (cardId, tier)
  - `quiz_answer` (questionId, correct, timeTaken)
  - `player_disconnect` / `player_reconnect` (seat, uid) ← ผูกกับข้อ 1
  - `match_end` (placement, duration, MMR delta)
  - (option) `error` — hook `Application.logMessageReceived` เก็บ LogError/Exception

### หมายเหตุ
- ยืนยันกับอาจารย์ว่าอยากได้ข้อมูลอะไรไปวิเคราะห์ แล้วค่อยเพิ่ม/ตัด event — schema generic รองรับอยู่แล้วไม่ต้องรื้อ
- ค่า `match_id` ใช้ `CurrentSessionName + "_" + เวลาเริ่มแมตช์` ให้ unique ต่อแมตช์

## ข้อ 1 — Reconnect: กลับเข้าแมตช์เดิม  🔴 (~2-2.5 สัปดาห์ งานใหญ่สุด)

### มีอยู่แล้ว (~40%)
- คนหลุด → seat เป็นบอทเล่นแทน: `GameController.Network.cs:133` `UpdateDisconnectedPlayerBotStatus`
- late-joiner ขอ full state: `RequestFullState()`/`STATEREQ` → host ส่ง board+economy+turn เฉพาะคนนั้น (`HandleFullStateRequested`, GameController.Network.cs:31)
- ตอน reconnect มี `isBot=false` + `RequestFullState()` แล้ว
- seat map เสถียร `_seatOrder` (FusionManager.cs)
- retry loop ตอน join ห้อง: `StartMatchedGameCoroutine` (FusionManager.cs:239)

### ⚠️ ช่องว่างหลัก
**PlayerId เปลี่ยนทุกครั้งที่เข้าห้องใหม่** → `_seatOrder` ผูก seat กับ PlayerId เก่า (หายไปแล้ว) คนกลับมากลายเป็น seat ใหม่ ไม่ทวง state เดิม

### งานที่ต้องทำ

**A. Identity ข้าม session (ฝั่ง state) — สัปดาห์ 2**
- [ ] เพิ่ม message `IDENT|uid` (uid = Supabase user id) — client ประกาศตอน `OnPlayerJoined`, **broadcast ทั้งห้อง** (ไม่ใช่แค่ authority — เผื่อ host migration)
- [ ] Authority เก็บ map `uid → seat` (persistent ตลอดแมตช์, replicate ให้ทุกเครื่อง)
- [ ] ตอนมี PlayerJoined ใหม่ + รับ IDENT:
  - uid เคยมี seat → **"กลับมา"**: remap `_seatOrder[seat] = PlayerId ใหม่`, `players[seat].isBot=false`, push full state ให้คนนั้น (ใช้ `HandleFullStateRequested` ที่มีแล้ว)
  - uid ใหม่ → seat ใหม่ปกติ
- [ ] เก็บ map ใน state ที่ authority ใหม่เข้าถึงได้ (เผื่อ host เดิมหลุด)

**B. Orchestration ฝั่ง client — สัปดาห์ 3**
- [ ] ดัก `OnShutdown` / `OnDisconnectedFromServer` (FusionManager.cs) → ถ้า `IsGameInProgress` → เริ่ม flow reconnect
- [ ] overlay "🔄 กำลังกลับเข้าเกม..." + เรียก `StartGame(Shared, roomCode เดิม, allowCreate=false)` วน retry
- [ ] หลัง join สำเร็จ → ส่ง `IDENT` ของตัวเอง → ขอ full state → ปิด overlay
- [ ] รองรับ **app ปิด/เปิดใหม่**: roomCode อยู่ใน PlayerPrefs (`MatchmakingRoomCode`) แล้ว — ตอนเปิดเกมเช็คว่ามีแมตช์ค้างไหม → เสนอ "กลับเข้าเกม"
- [ ] เคส host (authority) หลุด: คน PlayerId ต่ำสุดถัดไปรับช่วง (มี `AuthorityPlayer` logic แล้ว) — ทดสอบว่า uid map ยังอยู่
- [ ] เคสกลับมาตอนเกมจบแล้ว → เด้งหน้าผล/กลับเมนู

### จุดเสี่ยง (เผื่อเวลาไว้เยอะ)
- Photon session มี timeout — ถ้าหลุดนานเกิน ห้องอาจถูกปิด (ทดสอบ grace window จริง)
- uid map หายตอน host migration = bug ที่เจอบ่อย → ต้อง replicate ให้ทุกเครื่อง ไม่เก็บแค่ที่ host
- ต้องทดสอบ 2 เครื่องจริง + Android (libnanosockets เคยมีปัญหา — ดู memory)
