### สไลด์ที่ 3: ภาพรวมระบบและการเล่นหลัก (Core Gameplay Loop)
* **หัวข้อสไลด์:** กลไกการเล่นหลักของเกม (Core Loop)
* **เนื้อหาบนสไลด์:**
  * **กติกาอ้างอิง:** ประยุกต์ใช้กลไกการสร้างขุมพลังทรัพยากร (Engine-Building) จากบอร์ดเกม **Splendor**
  * **5 ทรัพยากรระบบคอมพิวเตอร์:** CPU, RAM, Network, Storage, Security
  * **3 แอคชั่นในแต่ละเทิร์น (เลือกทำ 1 อย่าง):**

  * **เงื่อนไขชัยชนะ:** สะสมแต้มดาวครบ **20 แต้ม** เป็นคนแรก

### สไลด์ที่ 4: ควิซแทรกชิงเทิร์นการเล่น (Interventional Quiz Mechanic)
* **หัวข้อสไลด์:** กลไกการสอดแทรกความรู้ (Gamified Quiz)
* **เนื้อหาบนสไลด์:**
  * **กติกาชิงเทิร์นเดินหมาก:** ทุกๆ 3 รอบการเล่น เกมจะหยุดและเด้งหน้าคำถามควิซให้ตอบพร้อมกันทุกคน
  * **ความรู้คอมพิวเตอร์ 5 หมวด:** สุ่มโจทย์สอดคล้องกับสีทรัพยากรในการ์ด
  * **เงื่อนไขชิงสิทธิ์:**
    * ตอบถูกและเร็วที่สุด (อันดับ 1) → ได้รับเหรียญทองพิเศษ + ได้เดินเทิร์นก่อนเป็นคนแรกในรอบถัดไป
    * ตอบถูกลำดับถัดมา (อันดับ 2-4) → ได้ลำดับเทิร์นเดินถัดไป
    * ตอบผิด → ตกไปอยู่ลำดับเทิร์นสุดท้าย
* **รูปภาพประกอบ:**
  * `[รูป: หน้าจอป๊อปอัพคำถามควิซ (Quiz Panel Interface) มีเวลานับถอยหลัง 10 วินาที และหน้าจอสรุปผลลำดับเทิร์นใหม่]`
* **บทพูดนำเสนอ (Presenter Note):**
  * *"จุดต่างสำคัญที่ทำให้เกมนี้เป็นสื่อการศึกษาคือระบบควิซแทรกทุก 3 รอบครับ ผู้เล่นต้องตอบคำถามแข่งกับเวลา 10 วินาที คนที่ตอบถูกและเร็วที่สุดจะได้สิทธิ์เดินก่อนในรอบถัดไปและได้เหรียญทอง เป็นการแปลงความรู้มาเป็นความได้เปรียบในตัวเกมครับ"*

### สไลด์ที่ 7: ระบบจับคู่และจัดการ Race Condition (Matchmaking)
* **หัวข้อสไลด์:** ระบบคิวจับคู่และการป้องกันข้อมูลชนกัน
* **เนื้อหาบนสไลด์:**
  * **ตรรกะระบบจับคู่ (Matchmaking Flow):**
    * ผู้เล่นกดจับคู่ → Client ส่งคำสั่งเข้า Supabase Edge Functions
    * เรียกใช้ Database Function ในระดับฐานข้อมูลชื่อ `claim_matchmaking_room`
  * **วิธีการกันข้อมูลชนกัน (Race Condition Prevention):**
    1. ใช้คำสั่ง **`SELECT ... FOR UPDATE`** เพื่อทำ Row-level Locking ล็อกแถวขณะรันธุรกรรม
    2. ใช้ **Unique Partial Index** บน ID ผู้เล่นในสถานะ 'waiting' ป้องกันการลงทะเบียนคิวซ้ำซ้อน
* **รูปภาพประกอบ:**
  * `[รูป: แผนภาพโฟลว์การทำงาน (Sequence Diagram) ของการทำ Matchmaking ระหว่าง Client กับ claim_matchmaking_room บน DB]`
* **บทพูดนำเสนอ (Presenter Note):**
  * *"ในระบบจัดหาห้องเล่นออนไลน์ เราประสบปัญหา Race Condition หากผู้เล่นกดพร้อมกันหลายคน ทีมงานจึงเลือกแก้ปัญหาในระดับฐานข้อมูล โดยการเขียน RPC Function ชื่อ claim_matchmaking_room ใช้คำสั่ง SELECT FOR UPDATE ล็อกแถวผู้ใช้และจัดเข้าห้องอย่างเสถียรและปลอดภัยครับ"*

### สไลด์ที่ 8: บอทคอมพิวเตอร์จำลอง (Rule-Based Bot AI)
* **หัวข้อสไลด์:** ระบบปัญญาประดิษฐ์ของคอมพิวเตอร์ (Bot AI)
* **เนื้อหาบนสไลด์:**
  * **ตรรกะกฎเกณฑ์ 4 ลำดับการตัดสินใจ (4-Level Priority System):**
    1. **ซื้อการ์ดเพื่อชนะ:** ตรวจสอบและซื้อการ์ดทันทีหากแต้มดาวจะครบ 20 คะแนน
    2. **ซื้อการ์ดคุ้มค่าสุด:** คำนวณความคุ้มค่าจากแต้มและราคาเพื่อเลือกซื้อใบที่ดีที่สุด
    3. **จองการ์ดระดับสูง:** เลือกจองการ์ด Tier 3 เพื่อสกัดคนเล่นและเก็บเหรียญทองพิเศษ
    4. **หยิบเหรียญสะสม:** หยิบเหรียญที่ยังขาดสำหรับการ์ดเป้าหมายสูงสุด
  * **4 บุคลิกจำลอง (Archetypes):** Balanced (สมดุล) · Aggressive (เน้นแต้มสูง) · Hoarder (เน้นจองตุนของ) · Specialist (โฟกัสเฉพาะสี)
* **รูปภาพประกอบ:**
  * `[รูป: โฟลว์ชาร์ตการตัดสินใจของบอท Rule-Based 4 ระดับ และรูปสัญลักษณ์ตัวละครที่เป็นตัวแทนของแต่ละสายอาชีพ]`
* **บทพูดนำเสนอ (Presenter Note):**
  * *"สำหรับโหมดเล่นคนเดียว เราสร้างบอท AI แบบ Rule-Based ที่มีลำดับตรรกะการตัดสินใจชัดเจน 4 ขั้น และแบ่งบุคลิกตามที่นั่งเป็น 4 รูปแบบ เพื่อไม่ให้บอทเล่นเหมือนกันในทุกเกม เพื่อเพิ่มท้าทายและความรู้สึกเหมือนเล่นกับผู้เล่นมนุษย์จริงครับ"*

### สไลด์ที่ 9: ความมั่นคงปลอดภัยและการป้องกันการโกง (Security & Anti-Cheat)
* **หัวข้อสไลด์:** ความมั่นคงปลอดภัยของระบบเครือข่ายและข้อมูล
* **เนื้อหาบนสไลด์:**
  * **Server-Authoritative Design:**
    * ทุกการคำนวณคะแนน MMR หรือสิทธิ์การได้รับ Gem รางวัลตอนจบเกม จะประมวลผลบนเซิร์ฟเวอร์คลาวด์เท่านั้น ป้องกันการดัดแปลงค่าข้อมูลจากตัวเกม (Client)
  * **Row-Level Security (RLS) Policies:**
    * ผู้เล่นทั่วไป (Role: `anon`) มีสิทธิ์อ่านคลังข้อสอบและตารางจัดอันดับเท่านั้น ไม่มีสิทธิ์เขียนลงตารางหลัก ยกเว้นการทำรายการผ่าน Edge Functions
  * **OTP Verification Encryption:**
    * รหัส OTP จะบันทึกในรูปแบบ SHA-256 Hash และจำกัดสิทธิ์การเดารหัสผ่านตัวแปร `attempts` ป้องกัน Brute-force
* **รูปภาพประกอบ:**
  * `[รูป: แผนภาพแสดงการบล็อกคำสั่งสิทธิ RLS บน Supabase จากตัวแฮกเกอร์ฝั่ง Client]`
* **บทพูดนำเสนอ (Presenter Note):**
  * *"ความมั่นคงปลอดภัยเป็นสิ่งสำคัญครับ โครงงานนี้ใช้สถาปัตยกรรมแบบ Server-Authoritative ฝั่ง Client จะส่งขึ้นไปแค่อันดับที่เล่นจบ ส่วนการบวกคะแนน MMR หรือ Gems จะคำนวณบนคลาวด์ทั้งหมด และเปิดนโยบาย RLS บน Supabase ทำให้ผู้เล่นไม่สามารถเขียนแก้ค่าหรือโกงระบบคะแนนได้ครับ"*

### สไลด์ที่ 10: ความสมบูรณ์ของระบบส่งมอบตามข้อตกลง (TOR Compliance Checklist)
* **หัวข้อสไลด์:** ผลการดำเนินงานและการส่งมอบงานจริงตามสัญญา (TOR)
* **เนื้อหาบนสไลด์:**
  * **ระบบตามสัญญา (TOR)**:
