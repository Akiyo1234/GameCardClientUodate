โครงงานวิจัยนี้มีวัตถุประสงค์เพื่อออกแบบและพัฒนาแอปพลิเคชันเกมการ์ดเชิงศึกษาบนอุปกรณ์เคลื่อนที่ เพื่อส่งเสริม
การเรียนรู้แนวคิดสถาปัตยกรรมระบบสารสนเทศและการบริหารจัดการทรัพยากรคอมพิวเตอร์ โดยประยุกต์ใช้กลไกการบริหาร
ทรัพยากรจากเกมกระดานค้าเพชร (Splendor) ร่วมกับการจ าลองกระบวนการประกอบโมดูลซอฟต์แวร์ ผู้เล่นจะได้รับบทบาทเป็น
นักพัฒนาระบบรุ่นใหม่ที่ต้องบริหารทรัพยากรระบบคอมพิวเตอร์ 5 ประเภท ได้แก่ CPU, RAM, Network, Storage และ Security 
เพื่อน าไปพัฒนาการ์ดโมดูลซอฟต์แวร์ที่แบ่งตามระดับความซับซ้อนออกเป็น 3 ระดับ (Tiers 1–3) เพื่อสะสมคะแนนแต้มระบบ 
(Stars) ให้ครบ 20 แต้มเป็นคนแรกเพื่อชัยชนะ 
ระบบโครงสร้างสถาปัตยกรรมได้รับการพัฒนาด้วยเครื่องมือ Unity และภาษา C# โดยรองรับโหมดการเล่นแบบผู้เล่นคน
เดียว (Single Player) ที่แข่งขันกับผู้เล่นจ าลองคอมพิวเตอร์ (Bot) ซึ่งควบคุมการท างานด้วยตรรกะเชิงกฎเกณฑ์ (Rule-Based 
System) ที่มีล าดับการตัดสินใจประเมินกระดาน 4 ระดับ และระบบหน่วงเวลาการตอบค าถามควิซให้ใกล้เคียงพฤติกรรมมนุษย์ 
ส าหรับโหมดการเล่นหลายคนแบบเรียลไทม์ (Real-time Multiplayer) รองรับผู้เล่น 2–4 คน ผ่านเครือข่ายความเร็วสูงด้วย Photon 
Fusion (Shared Mode) ตัวเกมบูรณาการร่วมกับฐานข้อมูลคลาวด์หลังบ้านของ Supabase และ PostgreSQL ซึ่งจัดการระบบ
สมัครสมาชิก ล็อกอินผู้ใช้งาน รวมถึงระบบคิวจับคู่อัตโนมัติ (Auto Matchmaking) ผ่านฟังก์ชันระดับฐานข้อมูล 
(`claim_matchmaking_room`) และจัดเก็บโปรไฟล์ผู้เล่น สถิติ MMR ตลอดจนสกินกรอบรูปโปรไฟล์อวตาร์ของผู้ใช้งานอย่างเป็น
รูปธรรม นอกจากนี้ยังมีการบูรณาการระบบแข่งขันตอบค าถามความรู้ด้านคอมพิวเตอร์ (Interventional Quiz) ทุกๆ 3 รอบการเล่น
เพื่อจัดล าดับเทิร์น และระบบทดสอบประจ าวัน (Daily Quiz) เพื่อสะสมเพชร (Gems) ส าหรับน ามาแลกกรอบรูปโปรไฟล์ในระบบ
ร้านค้าในเกม 
 
1. ที่มาและความส าคัญของปัญหา 
ในปัจจุบัน การเรียนรู้ด้านวิทยาการคอมพิวเตอร์ โดยเฉพาะด้านสถาปัตยกรรมระบบและการพัฒนาซอฟต์แวร์ (Software 
Development) เป็นเนื้อหาพื้นฐานที่มีความสำคัญต่อนักศึกษา อีกทั้งเนื้อหาดังกล่าวมีความหลากหลาย การเรียนรู้โดยอาศัยการ
ท่องจำเพียงอย่างเดียวอาจก่อให้เกิดความน่าเบื่อและทำให้ขาดแรงจูงใจในการศึกษา  
ด้วยเหตุนี้ ผู้จัดทำจึงเลือกแทรกคำถามระหว่างเล่นเกมเพื่อเสริมสร้างแรงจูงใจ และมีแนวคิดในการนำกลไกจากเกม 
Splendor (เกมค้าเพชร) ซึ่งเป็นเกมแนวบริหารจัดการทรัพยากรที่ประสบความสำเร็จสูง มาประยุกต์ใช้เป็นเครื่องมือการเรียนรู้ใน
รูปแบบเกมการ์ดดิจิทัล โดยเปลี่ยนกระบวนการสะสมเพชรมาเป็นการจัดการทรัพยากรระบบคอมพิวเตอร์ ได้แก่ CPU, RAM, 
Network, Storage และ Security เพื่อนำไปแลกซื้อการ์ดที่ทำเป็นธีมคอมพิวเตอร์

คอมพิวเตอร์ด้วยตรรกะเชิงกฎเกณฑ์ (Rule-Based Bot System) เพื่อเล่นกับผู้เล่นในโหมด Single Player และบูรณาการระบบควิซ
ประเมินความรู้คอมพิวเตอร์สอดแทรกระหว่างเล่น (Interventional Quiz) ทุกๆ 3 รอบการเล่น เพื่อผลักดันให้แอปพลิเคชันนี้ทำหน้าที่
เป็นสื่อการเรียนรู้เชิงปฏิสัมพันธ์ที่เปลี่ยนแนวคิดเชิงทฤษฎีที่เข้าใจยากให้กลายเป็นแบบจำลองกิจกรรมที่สนุกสนานและจับต้องได้จริง  
 
2. วัตถุประสงค์ 
2.1 เพื่อพัฒนาโมบายแอปพลิเคชันเกมการ์ดเชิงศึกษาที่จำลองกระบวนการบริหารจัดการทรัพยากร และการประกอบ 
โมดูลซอฟต์แวร์ด้วย Unity  
2.2 ระบบ Rules Based ที่พัฒนา Bot มาให้สามารถเล่นกับผู้เล่นได้เมื่อกดเล่นโหมด Single Player  
2.3 เพื่อพัฒนาและออกแบบระบบฐานข้อมูลให้รองรับกับการใช้งานของผู้ใช้ในระบบเกมการ์ดเสริมสร้างแนวคิด 
 
3. ขอบเขตของโครงการและการพัฒนา (Scope) 
โครงงานนี้มุ่งเน้นการออกแบบและพัฒนาเกมการ์ดดิจิทัลเชิงศึกษาที่รันอยู่บนอุปกรณ์พกพา รวมถึงระบบการซิงโครไนซ์
สถานะผู้เล่นหลายคนแบบเรียลไทม์ และระบบบริหารจัดการฐานข้อมูลคลาวด์หลังบ้าน โดยมีขอบเขตการทำงานจำแนกตามระบบย่อย

3.1 ระบบจัดการผู้ใช้งานและการยืนยันตัวตน (User Authentication & Web-based Registration) 
- ระบบลงทะเบียนสมาชิกใหม่ผ่านเว็บ (Web-based Registration): พัฒนาหน้าเว็บลงทะเบียน (index.html) 
แยกส่วนจากตัวเกมหลักด้วย HTML5, CSS (Vanilla CSS) และ JavaScript โดยรับข้อมูลชื่อผู้ใช้ (Username), อีเมล 
(Email) และรหัสผ่าน (Password) ของผู้เล่น จากนั้นส่งข้อมูลเชื่อมต่อไปยังบริการ Supabase Authentication เพื่อสมัคร
และบันทึกบัญชีลงทะเบียนใหม่ 
- ระบบล็อกอินและเข้าสู่ระบบในแอปพลิเคชัน (Application Login Scene): พัฒนาฉากการเข้าสู่ระบบ 
(LoginScece.unity) บนเอนจิน Unity เพื่อรองรับผู้เล่นในการกรอกอีเมลและรหัสผ่านเพื่อยืนยันตัวตนกับ Supabase Auth 
เมื่อการเข้าสู่ระบบผ่านการสิทธิ์เรียบร้อย ระบบจะดึงโปรไฟล์ส่วนตัวของผู้เล่นพร้อมส่งผู้ใช้งานไปยังหน้าต่างเมนูหลักของเกม
โดยอัตโนมัติ 
- ระบบแก้ไขข้อมูลส่วนตัว (Profile Customization): ผู้เล่นสามารถเข้าไปทำการแก้ไขหรือสลับการติดตั้งกรอบ
รูปโปรไฟล์อวตาร์ (Avatar Frames) ที่ได้รับจากการปลดล็อกผ่านระบบร้านค้าในภายหลังได้จากส่วนการตั้งค่าภายในแอป

3.2 ส่วนผู้ดูแลระบบสำหรับการจัดการคลังคำถาม (Web Admin Interface) 
- การบริหารคลังคำถามผ่านระบบคลาวด์ (Database Management Panel): ระบบสนับสนุนการทำงานของ
ผู้ดูแลระบบ (Admin) ในการเข้าถึงส่วนควบคุมของฐานข้อมูล Supabase เพื่อดำเนินการเพิ่ม (Create), เรียกดู (Read), 
แก้ไข (Update) และลบ (Delete) ข้อคำถามเชิงความรู้คอมพิวเตอร์ ซึ่งโครงสร้างข้อมูลประกอบด้วย โจทย์คำถาม, ตัว
เลือกตอบ 4 ตัวเลือก และดัชนีชี้เฉลยคำตอบที่ถูกต้อง 
- การอัปเดตแบบเรียลไทม์ (Dynamic Update Integration): ทุกการปรับแต่ง จัดการ หรือเปลี่ยนแปลง
คลังข้อมูลคำถามบนหลังบ้านของ Supabase จะถูกซิงค์เพื่อนำไปใช้แสดงผลในการเล่นของตัวเกมบนอุปกรณ์ผู้ใช้งานโดย
อัตโนมัติ 
 
3.3 ระบบห้องพักและการจับคู่ผู้เล่น (Matchmaking & Private Lobby System) 
- โหมดการเล่นคนเดียว (Single Player): รองรับระบบการทำงานที่เปิดโอกาสให้ผู้เล่นสามารถสร้างห้องเล่น
ส่วนตัวกับระบบผู้เล่นคอมพิวเตอร์ (Bot) จนครบตามจำนวนช่องว่างที่เหลือภายในห้อง 
- โหมดการสร้างห้องส่วนตัว (Private Lobby): ผู้เล่นสามารถเลือกสร้างห้องเล่นเกมส่วนตัว และระบบจะทำการ
สร้างรหัสห้องพัก (Room Code) เพื่อส่งต่อให้ผู้เล่นอื่นพิมพ์ป้อนรหัสผ่าน เพื่อเข้าร่วมกลุ่มเล่นร่วมกันในห้องเดียวกัน (รองรับ
จำนวน 2-4 คน) 
- โหมดจับคู่เล่นอัตโนมัติ (Auto Matchmaking Queue): พัฒนาสถาปัตยกรรมคิวการรอคอยและการจับคู่แบบ
เรียลไทม์บนฐานข้อมูลหลังบ้าน โดยอาศัยฟังก์ชันระดับฐานข้อมูล ได้แก่ claim_matchmaking_room และ 
cancel_matchmaking_search ในการบันทึกสถานะผู้เล่นเข้าตาราง matchmaking_queue และจัดสรรกลุ่มห้องจริงเข้า
ตาราง rooms บนระบบ Supabase 
- การเชื่อมโยงระบบเครือข่ายเรียลไทม์: ประยุกต์ใช้แพลตฟอร์ม Photon Fusion (Shared Mode) สำหรับการ
รับส่งข้อมูลโครงสร้างระบบเครือข่ายเพื่อทำการซิงโครไนซ์สถานะของเกม (Game States), ทรัพยากรกองกลาง, หน้าตัก
ทรัพยากรของผู้เล่น, การตัดสินรอบควิซ และการสลับลำดับเทิร์นการเล่นแบบเรียลไทม์สำหรับกลุ่มผู้เล่นจริง 
 
3.4 ระบบการเล่นหลักของเกมการ์ด (Core Gameplay Loop) 
- ธีมการนำเสนอและสภาพแวดล้อม: การดำเนินเนื้อเรื่องหลักของบอร์ดเกมเกิดขึ้นภายใต้เรื่องราวของวงการ
เทคโนโลยีและการแข่งขันแฮกกาธอน ประกอบด้วยฉากแผนที่หลัก 2 ฉากคือ "Startup City" และ "The Great 
Hackathon" 
- เป้าหมายการเอาชนะ (Win Condition): กำหนดให้ผู้เล่นทุกคนแข่งขันสะสมแต้มระบบ (Stars) จากการพัฒนา
การ์ดโมดูลซอฟต์แวร์ให้ครบ 20 แต้ม (Stars) เป็นคนแรก เมื่อมีผู้เล่นทำคะแนนถึงเกณฑ์แล้ว ระบบจะดำเนินเกมต่อไปให้
ครบจบรอบนั้น (เพื่อให้ผู้เล่นทุกคนในรอบนั้นมีจำนวนเทิร์นที่เท่ากันทั้งหมด) ก่อนเปรียบเทียบแต้มสะสมและประกาศชัยชนะ 
- เหรียญทรัพยากรระบบคอมพิวเตอร์ (System Resources): ประกอบด้วยทรัพยากรจำลองในรูปเหรียญ 5 
ประเภทหลัก ได้แก่ CPU, RAM, Network, Storage และ Security 
การ์ดโมดูลซอฟต์แวร์ 3 ระดับ (Software Module Tiers): 
     
 
- Tier 1 (ระดับพื้นฐาน): มูลค่าคะแนน 0–1 แต้ม (Stars) มีต้นทุนเหรียญทรัพยากรที่ต้องจ่ายในการพัฒนาต่ำ 
     
 
- Tier 2 (ระดับระบบย่อย): มูลค่าคะแนน 1–3 แต้ม (Stars) มีต้นทุนเหรียญทรัพยากรปานกลาง

หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการคอมพิวเตอร์  
คณะศิลปศาสตร์และวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ วิทยาเขตก าแพงแสน

 - Tier 3 (ระดับองค์กร): มูลค่าคะแนน 3–5 แต้ม (Stars) (สอดคล้องกับ TOR ข้อ 3.2.2 ที่ระบุแต้มการ์ดระดับ 3 
มีดาวระหว่าง 3-5 แต้ม) มีต้นทุนทรัพยากรสูง 
- การเลือกกระทำในตาเดิน (Turn Actions): เมื่อถึงคิวเทิร์นการเล่นของตนเอง ผู้เล่นสามารถเลือกทำ 
กิจกรรมหลักได้เพียง 1 อย่างจาก 3 รูปแบบต่อไปนี้: 
1. การรวบรวมทรัพยากร (Collect Resources): เลือกหยิบเหรียญทรัพยากรคอมพิวเตอร์ 
(CPU, RAM, Network, Storage, Security) จากกองกลางตามข้อกำหนดกติกา (หยิบเหรียญต่างกัน 3 สี 
หรือ หยิบเหรียญสีเดียวกัน 2 เหรียญหากมีจำนวนเหรียญในกองกลางเหลือมากกว่าเงื่อนไขขั้นต่ำ) 
2. การพัฒนาโมดูล (ซื้อการ์ด - Purchase Card): จ่ายทรัพยากรตามต้นทุนที่ระบุหน้าการ์ด 
เพื่อนำการ์ดเข้าพอร์ตการพัฒนาของตนเอง ส่งผลให้ได้รับแต้มคะแนนสะสม (Stars) และได้รับโบนัส
ลดหย่อนทรัพยากรสีนั้นๆ (ส่วนลดถาวร) สำหรับใช้ลดต้นทุนในการพัฒนาการ์ดใบถัดไปในรอบต่อไป 
3. การจองโมดูล (Reserve Card): เลือกจองการ์ดโมดูลบนบอร์ดชั่วคราวขึ้นมาเก็บไว้บนมือ
ของตนเอง (เก็บสะสมในมือได้ไม่เกิน 3 ใบ) เพื่อตัดโอกาสหรือสกัดผู้เล่นอื่น พร้อมรับเหรียญทรัพยากร
พิเศษ (Wildcard) 1 หน่วยเพื่อใช้ทดแทนเหรียญทรัพยากรสีใดๆ ก็ได้ 
 
3.5 ระบบผู้เล่นคอมพิวเตอร์ (Rule-Based Bot System) 
- พฤติกรรมการตอบสนองรอบควิชแบบเลียนแบบมนุษย์: บอทได้รับการออกแบบให้มีพฤติกรรมหน่วงเวลาสุ่มตอบ 
คำถาม โดยระบบจะสุ่มตอบในช่วง 5 วินาทีสุดท้าย จากกรอบเวลากลาง 10 วินาที 
- ตรรกะลำดับการตัดสินใจ (4-Level Priority System): บอทจำลองจะสแกนสถานะของกระดานเกมและหน้าตัก
ทรัพยากรที่มีอยู่ จากนั้นจะพิจารณาทำกิจกรรมที่ดีที่สุดตามเกณฑ์ลำดับความสำคัญ 4 ระดับดังนี้: 
- ลำดับที่ 1 (ซื้อการ์ดเพื่อชนะเกม): ตรวจสอบการ์ดบนกระดานและบนมือทั้งหมด หากมีใบใดที่บอท
จ่ายซื้อได้สำเร็จแล้วส่งผลให้แต้มดาวรวมสะสมเท่ากับหรือเกิน 20 แต้ม บอทจะทำการซื้อการ์ดใบนั้นและสิ้นสุด
รอบเกมทันที 
- ลำดับที่ 2 (ซื้อการ์ดที่ดีที่สุด/คุ้มสุด): ในกรณีที่ยังไม่สามารถปิดเกมได้ บอทจะคัดเลือกการ์ดที่จ่ายซื้อ
ได้และให้ค่าแต้มคะแนนดาวสูงที่สุดก่อน หากมีทางเลือกที่ให้คะแนนดาวเท่ากัน บอทจะตัดสินใจซื้อการ์ดที่มีราคา
ถูกที่สุด (ใช้ทรัพยากรรวมน้อยที่สุด) เพื่อความคุ้มค่า 
- ลำดับที่ 3 (จองการ์ดตัดหน้าเพื่อประหยัดทรัพยากร): หากเหรียญที่มีไม่เพียงพอในการซื้อการ์ดใบใด
เลย บอทจะทำการตรวจสอบหาการ์ดระดับสูง (Tier 3) ที่ตนเองต้องการนำมาพัฒนาและยังขาดแคลนเหรียญ
ทรัพยากรอีกเพียงเล็กน้อย (1-2 เหรียญ) บอทจะพิจารณาทำกิจกรรม "จองการ์ด" ใบนั้นขึ้นมือ เพื่อล็อกเป้าหมาย
และรับเหรียญพิเศษ (Wildcard) 
- ลำดับที่ 4 (หยิบเหรียญทรัพยากรเพื่อเตรียมพร้อม): หากไม่สามารถซื้อหรือจองการ์ดตามเงื่อนไขข้อ 
1-3 ได้ บอทจะทำกิจกรรมสแกนหาการ์ดโมดูลที่ต้องการพัฒนาสูงสุด และเลือกหยิบเหรียญทรัพยากรที่ยังขาด
แคลนมาจากกองกลางเพื่อสะสม

3.6 ระบบทดสอบความรู้และควิซ (Quiz System & Daily Quiz) 
- ระบบควิซประเมินความรู้คอมพิวเตอร์ระหว่างเล่นเกม (Interventional Quiz): ระบบจะเรียกเปิดหน้าต่าง 
คำถามทดสอบเชิงการศึกษาให้กับผู้เล่นทุกคนขึ้นมาตอบพร้อมกันในทุก ๆ 3 รอบการเล่น (ก่อนสลับไปดำเนินเทิร์นในรอบ 
ใหม่) ผู้เล่นที่เลือกคำตอบได้ถูกต้องและทำสถิติเวลาตอบเร็วที่สุด จะเป็นผู้ได้รับสิทธิ์เริ่มเล่นเป็นคนแรกในเทิร์นรอบถัดไป 
พร้อมได้รับเหรียญทรัพยากรพิเศษ (แบล็คคอยน์) เพิ่มเติม 1 เหรียญ นอกจากนี้ ในกรณีที่ผู้เล่นแข่งขันกับบอท (Al) ระบบได้ 
ออกแบบให้บอทมีพฤติกรรมเลียนแบบมนุษย์เพื่อสร้างความสมดุลของเกมเพลย์ (Game Balance) โดยบอทจะมีการหน่วง 
เวลาในตอบช่วง 5 วินาทีสุดท้าย จากกรอบเวลากลาง 10 วินาที 
- ควิซประจำวันเพื่อการประเมินศึกษาแบบเดี่ยว (Daily Quiz Scene): พัฒนาฉากจำลอง DailyQuizScene.unity 
แยกจากการแข่งขัน ให้ผู้เล่นทั่วไปสามารถเข้าทดสอบความรู้คอมพิวเตอร์แบบออฟไลน์ได้วันละ 1 ครั้ง เพื่อทบทวนวิชาการ
และสะสมแต้มเพชร (Gems) ในการนำมาแลกเปลี่ยนสกิน 
 
3.7 ระบบร้านค้าและการปรับแต่งโปรไฟล์ (Avatar Shop & Customization) 
- ระบบร้านค้าแลกเปลี่ยนด้วยระบบเหรียญรางวัล (Store Scene): พัฒนาฉากหน้าร้านค้าแลกเปลี่ยน 
(StoreScene.unity) รองรับผู้เล่นในการนำเพชร (Gems) ที่ได้จากการพิชิตเควสตอบควิซประจำวันหรือผลชัยชนะสะสม   
มาเลือกซื้อหรือปลดล็อกสกินกรอบรูปโปรไฟล์สไตล์ต่างๆ (Avatar Frames) 
- ระบบปรับปรุงอวตาร์โปรไฟล์: รองรับผู้เล่นในการเปิดใช้กรอบรูปโปรไฟล์พิเศษที่ได้ปลดล็อกแล้วเพื่อนำมาแสดง
ในสถิติโปรไฟล์ และแสดงประดับในตารางระบบจับคู่และจัดอันดับ 
 
3.8 ระบบจัดอันดับและสถิติประวัติการเล่น (Leaderboard & Match History) 
- ตารางผู้นำและระบบจัดอันดับเรียลไทม์ (Leaderboard): ระบบพัฒนาให้ทำการจัดสรรแสดงผลอันดับคะแนน    
ผู้เล่นเรียงลำดับจากค่า MMR (Matchmaking Rating) จากสูงสุดลงมา โดยการคัดกรองข้อมูลผู้ใช้งานจากตาราง 
player_profiles ในฐานข้อมูล Supabase นำมาจัดอันดับและแสดงผลลัพธ์ในหน้าจอจัดอันดับ (RankScene.unity) 
- ระบบจัดเก็บประวัติการแข่งขัน (Match History & Statistics): ระบบหลังบ้านทำหน้าที่คอยอัปเดตสถิติจำนวน
ตาที่เล่นชนะ (Wins) และจำนวนตาที่แพ้ (Losses) ของแต่ละบัญชีผู้ใช้งานลงฐานข้อมูลอย่างเสถียรหลังจากการสรุปผลชัย
ชนะในแต่ละเกมกระดาน

4. ทบทวนวรรณกรรม (Literature Review) 
ในการออกแบบและพัฒนาระบบเกมการ์ดเสริมสร้างแนวคิดระบบสารสนเทศ ผู้จัดท าได้ด าเนินการศึกษาและรวบรวม
ทฤษฎี หลักการ และเทคโนโลยีที่เกี่ยวข้องเพื่อน ามาประยุกต์ใช้เป็นแนวทางในวิจัยและการพัฒนาซอฟต์แวร์จ าลอง โดยสามารถ
สรุปรายละเอียดโครงสร้างแนวคิดได้ดังต่อไปนี้: 
 
4.1 ศึกษาระบบงานที่ใกล้เคียง 
ผู้จัดท าได้ศึกษาและวิเคราะห์สถาปัตยกรรมการท างาน ข้อดี และข้อจ ากัดของแอปพลิเคชันระบบเกมเชิง
พาณิชย์และระบบสื่อการเรียนรู้สองระบบเพื่อน ามาใช้เป็นแนวทางในการออกแบบ ได้แก่: 
 
4.1.1 แอปพลิเคชัน Ephod (Mobile Board Game) 
- แอปพลิเคชัน Ephod เป็นเกมจ าลองบอร์ดเกม Splendor (เกมค้าเพชร) บนอุปกรณ์เคลื่อนที่ใน
รูปแบบดิจิทัล โดยเน้นตรรกะการบริหารจัดการทรัพยากร (Resource Management) และการคิดค านวณแต้ม
ส่วนลดหย่อนถาวร (Discount Logic) เพื่อลดหย่อนราคาการ์ดในเทิร์นถัดไป 
- แนวคิดที่ประยุกต์ใช้: ผู้จัดท าได้น ากลไกการถ่วงดุลทรัพยากร (Game Balancing) และแนวทางการ
แลกเปลี่ยนการ์ดของ Ephod มาใช้เป็นต้นแบบในการค านวณสมดุลโครงสร้างของการ์ด 3 ระดับ และการแปลง
มูลค่าโบนัสให้เป็นสัญลักษณ์ทรัพยากรระบบสารสนเทศ 
- ข้อจ ากัดของระบบเดิม: Ephod มุ่งเน้นการเล่นเพื่อความบันเทิงและไม่ได้สอดแทรกเนื้อหาเชิง
วิชาการหรือการประเมินความรู้ที่เป็นระบบ

4.1.2 แอปพลิเคชัน Plato (Social Gaming Platform) 
- Plato เป็นแพลตฟอร์มโซเชียลเกมมิ่งบนอุปกรณ์เคลื่อนที่ที่ได้รับความนิยมสูง จุดเด่นคือระบบการ
เชื่อมต่อแบบเรียลไทม์หลายผู้เล่น (Real-time Multiplayer) และความเร็วในการตอบสนองซิงโครไนซ์ข้อมูล
เครือข่ายระหว่างห้องเล่นที่เสถียร รวมถึงมีฟังก์ชันการสลับสกินกรอบรูปโปรไฟล์และการปรับแต่งตัวละครเพื่อ
กระตุ้นปฏิสัมพันธ์ของผู้ใช้งาน 
- แนวคิดที่ประยุกต์ใช้: ผู้จัดท าน ารูปแบบการจัดสัดส่วนห้องพัก (Lobby System) การแสดงสถานะผู้
เล่นแบบเรียลไทม์ และระบบร้านค้าแลกซื้อสกินโปรไฟล์ผู้ใช้งานของ Plato มาออกแบบโครงสร้างหน้าล็อบบี้
และการควบคุมร้านค้าในเกม 
- ข้อจ ากัดของระบบเดิม: โครงสร้างสตรีมมิ่งเครือข่ายของ Plato ต้องพึ่งพาการท างานของเครื่องแม่
ข่ายหลักขนาดใหญ่ที่มีค่าใช้จ่ายสูงและมีความซับซ้อนในระดับโปรโตคอล

4.2 เครื่องมือและเทคโนโลยีที่ใช้ในการพัฒนาระบบ 
- ในการติดตั้งและพัฒนาแอปพลิเคชันระบบเกมและฐานข้อมูลหลังบ้านจริง ผู้จัดท าเลือกใช้ชุดเทคโนโลยีชั้นน า 
(Tech Stack) ที่รองรับการท างานแบบข้ามแพลตฟอร์ม ดังต่อไปนี้: 
4.2.1 Unity Game Engine

Logic ด้วยภาษา C# ท าหน้าที่รันองค์ประกอบด้านกราฟิกจ าลอง หน้าจอส่วนติดต่อผู้ใช้งาน (UI) แอนิเมชัน 
และการตอบสนองเชิงฟิสิกส์ทั้งหมดภายในแอปพลิเคชันเกม ทั้งในฉากการเล่นหลัก (SampleScene.unity) 
ควิซประจ าวัน (DailyQuizScene.unity) และร้านค้า (StoreScene.unity)

4.2.2 Photon Fusion (Shared Mode) 
- เป็นชุดพัฒนาโปรโตคอลเครือข่าย (Network SDK) ประสิทธิภาพสูงที่ท างานอยู่บนสถาปัตยกรรม
คลาวด์จ าลอง (Cloud Session) ใช้ส าหรับซิงโครไนซ์ข้อมูลสถานะกระดานเกม ล าดับผู้เล่น ข้อมูลทรัพยากรใน
มือ และข้อมูลค าตอบควิซระหว่างไคลเอนต์แบบเรียลไทม์ในห้องออนไลน์ (Multiplayer Room) ช่วยแก้ปัญหา
การเหลื่อมเวลาการตอบและการจัดอันดับความเร็วได้อย่างแม่นย า 
4.2.3 Supabase และระบบฐานข้อมูล PostgreSQL 
- บริการฐานข้อมูลคลาวด์หลังบ้าน (Backend-as-a-Service: BaaS) ที่ใช้ PostgreSQL เป็นระบบ
จัดการฐานข้อมูล (RDBMS) หลักในการเก็บข้อมูล 
- การเชื่อมโยงระบบ: ตัวเกมเชื่อมต่อ Supabase ผ่าน Gotrue API ส าหรับสมัครสมาชิกและยืนยัน
สิทธิ์ผู้ใช้ (Supabase Auth)  
- การประยุกต์ใช้ Database Function: ใช้ฟังก์ชัน SQL ภายในฐานข้อมูล ได้แก่ 
claim_matchmaking_room และ cancel_matchmaking_search ร่วมกับกลไก advisory lock ในการบริหาร
จัดคิวในตาราง matchmaking_queue และจัดสรรห้องในตาราง rooms ในระดับเซิร์ฟเวอร์แบบเรียลไทม์เพื่อ
ป้องกันสภาวะแข่งขัน (Race Conditions) 
4.2.4 Visual Studio Code และ Visual Studio 
- เครื่องมือแก้ไขและเขียนชุดค าสั่งหลัก (Source Code Editor) ที่ใช้ส าหรับการพัฒนาไฟล์ควบคุม
ภาษา C# ภายในโครงการ Unity และใช้ส าหรับพัฒนาสถาปัตยกรรมหน้าเว็บลงทะเบียน (index.html) ที่
เชื่อมโยงเข้ากับระบบสมัครสมาชิกของ Supabase Client SDK v2 
4.2.5 Android Studio 
- เครื่องมือและสภาพแวดล้อมหลักในการพัฒนาแอปพลิเคชันบนระบบปฏิบัติการ Android ใช้ใน
ขั้นตอนการจ าลองฮาร์ดแวร์อุปกรณ์ (Android Emulator) ส าหรับทดสอบการแสดงผลและดีพลอยด์สร้างไฟล์

4.2.6 Git และ GitHub 
- ระบบควบคุมการจัดเก็บเวอร์ชันของโค้ดโปรแกรม (Version Control System) และพื้นที่จัดเก็บซอร์

5. วิธีการดำเนินงานและการออกแบบระบบ 
การพัฒนาระบบเกมการ์ดเสริมสร้างแนวคิดระบบสารสนเทศ ได้ดำเนินการตามระเบียบวิธีวิจัยและขั้นตอนทางวิศวกรรม
ซอฟต์แวร์ (Software Engineering) เพื่อให้เกิดความสมบูรณ์ในการทำงานประสานกันระหว่างฝั่งผู้ใช้งานบนอุปกรณ์พกพา เซิร์ฟเวอร์
แบบเรียลไทม์ และระบบบริหารคลังข้อมูลบนระบบคิวคลาวด์หลังบ้าน โดยขั้นตอนการดำเนินงานและการออกแบบส่วนประกอบต่างๆ 
มีรายละเอียดดังต่อไปนี้: 
5.1 ระเบียบวิธีวิจัยและการดำเนินงาน (Research Methodology & Timeline) 
5.1.1 ขั้นตอนและกระบวนการทำงาน 
- การศึกษาและเก็บข้อมูล: ศึกษารูปแบบหลักสูตรวิทยาการคอมพิวเตอร์และสถาปัตยกรรมระบบ
สารสนเทศเพื่อระบุประเภทคลังข้อสอบ 5 หมวดหลัก (CPU, RAM, Storage, Network, Security) พร้อมทั้ง
วิเคราะห์ฟีเจอร์เกมแบบจับคู่ออนไลน์และการเล่นเกมแบบมีปฏิสัมพันธ์ (Interactive Multi-player Board 
Game) 
- การออกแบบสถาปัตยกรรมระบบและฐานข้อมูล: กำหนดโครงสร้างความสัมพันธ์และพจนานุกรมข้อมูล 
(Data Dictionary) ในระบบฐานข้อมูลคลาวด์ (Cloud Database) และออกแบบแผนภาพระดับระบบ (Data Flow 
Diagram และ Core Gameplay Flowchart) 
- การพัฒนาระบบและติดตั้ง: พัฒนาระบบไคลเอนต์ด้วย Unity Engine และ Photon Fusion 2 ร่วมกับ
การทำงานฐานข้อมูลเรียลไทม์ผ่าน RESTful API ของ Supabase และสร้างอินเทอร์เฟซสมัครสมาชิกสำหรับผู้เรียน
ผ่านเว็บ 
- การทดสอบและประเมินผลระบบ: ดำเนินการประเมินตรรกะการตัดสินใจของระบบบอทอัตโนมัติ (Bot 
decision windows) และการจัดตารางเวลาควิซ รวมถึงประเมินประสิทธิภาพการไหลของข้อมูลคิวจับคู่ และนำ
ระบบไปทดสอบความพึงพอใจการใช้งานของกลุ่มตัวอย่างผู้ใช้จริง

7.1 ผลที่คาดว่าจะได้รับ 
7.1.1 ผู้เรียนได้เลือกและเข้าใจโครงสร้างระบบเทคโนโลยีสารสนเทศพื้นฐาน 
- ผู้เรียนมีความเข้าใจสถาปัตยกรรมคอมพิวเตอร์ 5 มิติ (CPU, RAM, Storage, Network, Security) 
ผ่านกระบวนการแลกเปลี่ยนทรัพยากรและการประกอบโมดูลการ์ด Tiers 1-3 ตามกฎของเกม ช่วยลดความเบื่อ
หน่ายในการศึกษาจากต าราปกติ 
7.1.2 ผู้เรียนได้รับการกระตุ้นความจ าและทักษะการวิเคราะห์ผ่านค าถามควิซในเวลาจ ากัด 
- ควิซวิชาการคั่นระหว่างการเล่นทุก ๆ 3 เทิร์น (เวลา 10 วินาที) ช่วยกระตุ้นความจ าและการคิด
วิเคราะห์เพื่อแย่งชิงสิทธิ์ล าดับตาเดิน (Turn Order) ในรอบถัดไป

7.4 ข้อเสนอแนะ 
7.4.1 ควรเพิ่มระบบแสดงความรู้สึก หรือข้อความสั้นส าเร็จรูปในห้องรอจับคู่และระหว่างตาเดิน 
- เพื่อส่งเสริมการสร้างปฏิสัมพันธ์ทางสังคมและการเรียนรู้ร่วมกันระหว่างผู้เล่น 
7.4.2) ควรพัฒนาหน้าเว็บพอร์ทัลควบคุมคลังข้อสอบผ่านคลาวด์ส าหรับผู้สอน  
- เพื่อให้อาจารย์ผู้ประสานงานสามารถปรับปรุงข้อมูลข้อสอบหรือเพิ่มลบชุดข้อสอบได้โดยตรงโดยไม่
ต้องท าการอัปเดตไฟล์เกม 
7.4.3 ควรพัฒนาระบบบอทออฟไลน์ให้สามารถปรับเปลี่ยนระดับความเก่งตามฝีมือผู้เล่นโดยอัตโนมัติ  
- เพื่อยกระดับความท้าทายและความลื่นไหลในการฝึกฝนทักษะการเรียนรู้ของผู้เรียนแต่ละบุคคลได้
